### 1. Phía Cổng mạng & Máy chủ Google (Tại sao lại đúng con số 300 giây?)

Trong code của `mhc` **không có dòng lệnh `setTimeout` nào tự đặt 300 giây**. Con số 300 giây đến từ 2 tầng hạ tầng của Google:

1. **Giới hạn 300s của Cổng Reverse Proxy / Cloud Run (Gateway Timeout):**
   - Khi `mhc` chạy trên hạ tầng container của Google (Cloud Run / AI Studio Hosting / Reverse Proxy), cổng mạng đứng trước ứng dụng có **HTTP Request Timeout cứng là 300 giây**.
   - Nếu sau đúng 300 giây mà API `/api/translate` chưa trả về hoàn tất, cổng Proxy sẽ cưỡng bức ngắt kết nối và trả về lỗi văn bản thuần `"upstream request timeout"` hoặc HTTP `504 Gateway Timeout` (được bắt tại [`mhc/lib/logger.ts` (dòng 580–616)](file:///c:/Users/Admin/Documents/Codex/2026-07-24/sites-plugin-sites-openai-bundled-create-2/mhc/lib/logger.ts#L580-L616)).
2. **Độ trễ xử lý của cổng Gemini Interactions API (`v1beta/interactions`):**
   - Khi gọi Gemini với **Structured Output (JSON Schema)** kèm suy luận sâu, máy chủ Google không trả dữ liệu ngay mà phải hoàn tất bước suy nghĩ ngầm (Thinking) rồi mới giải mã chuỗi JSON. Vào khung giờ cao điểm hoặc khi gặp chương dài, hàng đợi nội bộ của Google bị nghẽn khiến thời gian phản hồi kéo dài từ 120s lên tới hơn 300s.

### Cổng số 1: Giữa Trình duyệt $\leftrightarrow$ Server Next.js (`mhc`)
- **Khi chạy trên AI Studio (Preview / Publish link `ai.studio`):**
  - Có một cổng **Reverse Proxy / Cloud Run của Google** đứng chắn ở giữa. Cổng này đếm giờ từ lúc trình duyệt bấm "Dịch" gửi vào `/api/translate`: cứ đúng **300 giây** (hoặc 60s–300s tùy lúc cổng nghẽn) mà server chưa trả xong kết quả là nó cắt đứt ngay và báo lỗi `"upstream request timeout"`.
  - Do đó, nếu Key #1 chạy mất 160s bị lỗi, rồi xoay sang Key #2 chạy thêm 150s (tổng 310s) $\rightarrow$ **Chạy trên AI Studio sẽ bị cắt chết ở giây 300.**
- **Khi chạy Local (`npm run dev` trên máy bạn):**
  - Trình duyệt gọi thẳng vào `localhost:3000` trên máy bạn, **không đi qua cổng Proxy của AI Studio**.
  - Vì vậy, nếu Key #1 mất 160s + xoay sang Key #2 mất 150s (tổng 310s hay 500s) $\rightarrow$ **Chạy Local KHÔNG BỊ NGẮT, vẫn nhận được bản dịch bình thường!**

---

### Cổng số 2: Giữa Server `mhc` (trên máy bạn) $\leftrightarrow$ Máy chủ AI của Google (`googleapis.com`)
Ngay cả khi bạn chạy `npm run dev` ở Local, khi server `mhc` gọi SDK `@google/genai` sang máy chủ Google vẫn còn **2 chốt chặn 300 giây** cho **mỗi một lần gọi Key**:

1. **Giới hạn `headersTimeout = 300 giây` mặc định của Node.js trên máy bạn:**
   - Node.js (v18/v20/v22) sử dụng bộ nhân mạng `undici` cho hàm `fetch()`. Mặc định, `undici` cài cứng thông số **`headersTimeout = 300_000 ms` (đúng 300 giây)**.
   - Vì code `mhc` gọi Gemini theo kiểu **không Streaming** (phải chờ AI suy nghĩ xong + viết xong 100% chuỗi JSON của cả chương thì Google mới gửi HTTP Header phản hồi đầu tiên về), nên nếu 1 chương quá dài + để `thinking_level: "high"` khiến Google mất hơn 300 giây chưa trả lời xong $\rightarrow$ **Chính Node.js trên máy bạn sẽ tự cắt kết nối ở giây 300** (báo lỗi `fetch failed` / `UND_ERR_HEADERS_TIMEOUT`).
2. **Cổng Google Front End (`generativelanguage.googleapis.com`):**
   - Phía trước máy chủ AI Gemini của Google cũng có cổng mạng tiếp nhận API. Với các lệnh gọi thông thường (không streaming), nếu 1 lệnh đơn lẻ chạy quá ~300 giây mà chưa sinh xong JSON, cổng API của Google cũng tự ngắt và trả về lỗi `504 DEADLINE_EXCEEDED` hoặc `503`.
